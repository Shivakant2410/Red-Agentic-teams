What the system is

An authorized red team agent. It maps a target, forms a hypothesis, runs a cheap experiment, and records a finding only when that finding reproduces and a benign control fails to reproduce it. Rented intelligence, owned harness: the models are free OpenRouter endpoints, and everything defensible lives in the scaffolding around them — a knowledge graph of the target, an access graph of what the operator holds, a kill chain, and a verifier.

Every claim carries one of four verdicts. A claim that cannot earn the first one is not recorded:

  • confirmed
  • not_reproducible
  • falsified
  • rejected

Changing the scoreboard

Recall against a vulnerability list is a scanner's metric, and optimising it kept producing a better scanner. From run 10 the measure became the one a red team is actually judged on: was the objective reached, by what path, how fast, and how loudly. Findings became a secondary signal. What the tests could not see

The suite was green throughout. Three of these four defects existed only in the live request-and-replay path, which fakes never exercise; the fourth was a scoring rule that flattered us.

Null content replayed to the API

A model that stops often returns content: null. That was harmless while the loop broke immediately, but once the loop continued the message was replayed and every model answered HTTP 400. Run 11 died after four turns.

FixNormalise null content before replay. A regression test asserts that no replayed message ever carries it.

Degenerate responses read as decisions

Free endpoints regularly answer with no content, no tool calls and no usage. These were logged as success and interpreted as the agent choosing not to act, so the loop concluded it had finished. Measured at roughly 20% of calls.

FixA response with neither content nor tool calls is a failed attempt, and the router rotates to another model. Every earlier run was measured through this noise.

A label satisfied a privilege claim

The agent named its own session admin. Scoring matched that string against the "become administrator" criterion, so a privilege claim needed no evidence at all.

FixPrivilege criteria may only be credited by a differential proof: the action succeeds as the elevated identity and fails as the lower one. Run 13 was re-scored from 2 of 3 down to 1 of 3.

Unbounded response reads

The HTTP layer read a full response body with no ceiling, so a target could return an endless body and exhaust the agent's memory. An older package in this same repository had already solved this, and the newer code did not borrow it.

FixBodies are streamed and capped at 256 KB with an explicit truncation marker.

Corrections to the record

Run 13 was reported as 2 of 3 criteria. The administrator criterion had been credited because the agent named its own session admin, so it was never evidenced. The honest figure is 1 of 3, and the better-looking number was withdrawn.

Roughly a fifth of all model calls in runs 1 through 12 returned degenerate responses that were counted as the agent declining to act, so every comparison drawn from those runs was noisier than it was presented to be. Recall also swung between 0.20 and 0.60 on near-identical configurations, which makes the single-run comparisons in this ledger weak evidence. Later measurement reports distributions instead.

A check that cannot fail correctly is worse than no check. One secret scan here reported a leaked API key that did not exist, because the shell tested the wrong exit status.

Where it stands

The verifier is the part that works. Across every run it never recorded a finding it could not reproduce, and the negative control correctly refuses a claim when a benign request produces the same signal. Precision is the moat.

The gap is exploitation depth. The agent can plan a kill chain but cannot yet walk one: no traffic interception, no way to write its own exploit, and until recently its sandbox could not reach a target on localhost at all. That, rather than caution, is what made it read as a scanner, and it is what the next phase builds.
